ВСТУП

Під час практики я зосередився на вивченні фреймворку Next.js та переносі існуючого веб-проекту OaEdu з React (Vite) на Next.js з використанням App Router. Цей напрямок актуальний для сучасної веб-розробки, оскільки Next.js надає серверний рендеринг, покращене SEO, файлову маршрутизацію та інтеграцію з сучасним стеком React.

Метою практики було: ознайомитися з офіційним курсом Learn Next.js на платформі nextjs.org/learn, засвоїти основи React Foundations, App Router, Pages Router та SEO; виконати повний перенос проекту OaEdu (освітня платформа Острозької академії) у новий проект oaedunextjs зі збереженням функціональності, захисту маршрутів та додаванням SEO-оптимізації.

Результатом стало повністю робочий проект на Next.js 16 з перенесеними сторінками (головна, розклад, новини, волонтерство, адмін-панель), авторизацією, layout-ами та налаштованими metadata, sitemap та robots для пошукових систем.

ПРЕДМЕТНЕ СЕРЕДОВИЩЕ

3.1 Опис системи та користувачі

OaEdu — веб-застосунок освітньої платформи Національного університету «Острозька академія». Система призначена для інформаційної підтримки навчального процесу: перегляд розкладу занять, отримання новин університету, ознайомлення з можливостями волонтерства та (для адміністраторів) управління довідниками та контентом через адмін-панель.

Користувачі системи:

Здобувач (студент, викладач) — авторизований користувач, який переглядає головну сторінку, розклад занять, новини; має доступ до особистого кабінету після входу (Login). Не має доступу до адмін-панелі.

Адміністратор — користувач з роллю «Admin», який крім перегляду має доступ до розділу AdminPanel: управління розкладами, викладачами, предметами, спеціальностями, ролями, кафедрами, групами, типами занять, номерами пар, новинами та волонтерством.

Публічні можливості (без авторизації): перегляд сторінки входу (Login), розділу «Новини» (категорії та статті), розділу «Волонтерство» (список та деталі). Захищені розділи (головна, розклад) та AdminPanel потребують авторизації; AdminPanel — додатково перевірки ролі.

3.2 Функціональна модель та процес діяльності

Основні функціональні підсистеми:

1. Автентифікація — вхід за логіном/паролем, збереження JWT-токена, перевірка прав доступу при переході на захищені маршрути.

2. Інформаційні сторінки — головна (HomePage), розклад (schedule з фільтрами за групою/викладачем/датою), новини (категорії: загальні, спорт, події, наука, культура; сторінка деталей новини), волонтерство (список та деталі оголошень).

3. Адміністрування — CRUD для сутностей: розклади, викладачі, предмети, спеціальності, ролі, кафедри, групи, типи занять, номери пар, новини, волонтерство. Кожен підрозділ має таблицю, форму додавання/редагування, пошук за ID або іншими полями.

Процес діяльності (спрощено): користувач відкриває сайт → переглядає публічні розділи (новини, волонтерство) або переходить на вхід → після авторизації отримує доступ до головної та розкладу; адміністратор додатково отримує доступ до AdminPanel і виконує операції з довідниками та контентом. Усі дані для відображення та змін надходять з зовнішнього API (бекенд); фронтенд (oaedunextjs) відповідає за інтерфейс, маршрутизацію, захист маршрутів та виклики API.

АРХІТЕКТУРА РІШЕННЯ

4.1 Загальна архітектура (Next.js App Router)

Рішення oaedunextjs побудоване на Next.js 16 з використанням App Router. Це означає файлову маршрутизацію: кожен каталог у src/app/ з файлом page.tsx відповідає URL-шляху; layout.tsx у папці визначає спільний layout для усіх дочірніх маршрутів. Група маршрутів (main) не додає сегмента до URL, але дозволяє спільний layout (MainLayout) для головної, розкладу, новин, волонтерства та адмін-панелі.

Рівні архітектури:

Клієнт (браузер) — отримує HTML/CSS/JS, виконує клієнтські компоненти (наприклад, форми, ProtectedRoute, інтерактивні списки).

Next.js (сервер + клієнт) — серверний рендеринг кореневого HTML, генерація metadata для SEO, обслуговування статики; клієнтська навігація після першого завантаження (SPA-подібна поведінка в межах App Router).

Зовнішній API (бекенд) — автентифікація, отримання розкладів, новин, волонтерства, довідників; всі запити йдуть через один базовий URL (наприклад, NEXT_PUBLIC_API_URL), з додаванням заголовка Authorization: Bearer <token> та при необхідності X-User-Id.

Стек: React 19, TypeScript, MUI 7 (Material-UI) з Material-NextJS для сумісності з App Router, Tailwind CSS, axios для HTTP, jwt-decode для перевірки токена.

4.2 Маршрутизація, layout-и та захист

Кореневий layout (app/layout.tsx) — задає мову сторінки (uk), глобальні метадані (title, description, openGraph), обгортає додаток у провайдери: AppRouterCacheProvider (MUI), AuthProvider (стан авторизації), ThemeProvider (світла/темна тема).

Вкладені layout-и: (main)/layout.tsx повертає MainLayout (Header + Footer); усередині (main) окремі гілки можуть мати власний контекст (наприклад, news/layout.tsx з NewsLayout і metadata «Новини», AdminPanel/layout.tsx з AdminLayout і ProtectedRoute role="Admin").

Захист маршрутів реалізований патерном ProtectedRoute: клієнтський компонент перевіряє isAuthenticated та (опційно) роль користувача; при невиконанні умов виконується редірект на /Login. Захищені сторінки (головна, розклад) та layout AdminPanel обгорнуті в <ProtectedRoute> або <ProtectedRoute role="Admin">.

4.3 Сервісний шар та інтеграція з API

Клієнт не викликає API напряму з компонентів; використовується сервісний шар: клас HttpClient (axios) з базовим URL, таймаутом та інтерцепторами. Інтерцептори автоматично додають до запитів заголовок Authorization з токеном з localStorage та (за наявності) X-User-Id; при відповіді 401 токен видаляється і користувач перенаправляється на Login. Окремі сервіси (AuthService, NewsService, ScheduleService, TeacherService тощо) створюють екземпляр HttpClient і експортують методи get, post, put, delete для відповідних ендпоінтів. Компоненти викликають ці сервіси (наприклад, ScheduleService.getAll(), AuthService.login()), що забезпечує єдину точку конфігурації та обробки помилок авторизації.

Лістинг 2.А. Конфігурація Next.js — rewrites для API та webpack для SVG (додано при переносі, next.config.ts)

import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  reactCompiler: true,
  async rewrites() {
    const backendUrl = process.env.API_BACKEND_URL || "http://localhost:8000";
    return [{ source: "/api/:path*", destination: `${backendUrl}/:path*` }];
  },
  webpack(config) {
    config.module.rules.push({
      test: /\.svg$/i,
      issuer: /\.[jt]sx?$/,
      use: ["@svgr/webpack"],
    });
    return config;
  },
};
export default nextConfig;

private initInterceptors() {
  this.axiosInstance.interceptors.request.use((config) => {
    if (typeof window !== "undefined") {
      const token = localStorage.getItem("token");
      if (token) config.headers["Authorization"] = `Bearer ${token}`;
      const userId = getUserIdFromToken();
      if (userId) config.headers["X-User-Id"] = userId;
    }
    return config;
  }, (error) => Promise.reject(error));
  this.axiosInstance.interceptors.response.use(
    (response) => response,
    (error) => {
      if (typeof window !== "undefined" && error?.response?.status === 401) {
        localStorage.removeItem("token");
        window.location.href = "/Login";
      }
      return Promise.reject(error);
    }
  );
}
public async get<T>(url: string, config?: AxiosRequestConfig): Promise<T> {
  return this.axiosInstance.get(url, config).then((r) => r.data as T);
}

"use client";
const hasRole = (userRole: string, role?: string | string[]) => {
  if (!role) return true;
  if (Array.isArray(role)) return role.includes(userRole);
  return userRole === role;
};
const ProtectedRoute = ({ role, children, redirectTo = "/Login" }) => {
  const router = useRouter();
  const { isAuthenticated } = useAuth();
  const { user, loading } = useCurrentUser();
  const shouldRedirect = !loading && (!isAuthenticated || !user || !hasRole(user?.role_name ?? "", role));
  useEffect(() => { if (shouldRedirect) router.push(redirectTo); }, [shouldRedirect, redirectTo, router]);
  if (loading) return <Loader />;
  if (shouldRedirect) return null;
  return <>{children}</>;
};
